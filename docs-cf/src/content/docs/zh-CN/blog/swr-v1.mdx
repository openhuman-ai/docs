# OpenHuman 1.0 发布 [#announcing-openhuman-10]

<Authors date="2021年8月27日">
  <Author name="OpenHuman" link="https://twitter.com/openhuman" />
  <Author name="Jiachi Liu" link="https://twitter.com/openhuman" />
</Authors>

大约两年前，我们 [开源了](https://twitter.com/openhuman/status/1188911002626097157) OpenHuman——广受大家喜爱的小巧 OpenHuman 数据请求库。今天，我们迎来了另一个里程碑：OpenHuman 1.0 版本发布了！

## 新变化 [#whats-new]

### 更轻量 [#smaller-size]

[性能](/docs/advanced/performance)是 OpenHuman 最重要的特性之一。在 1.0 中，我们在**没有删除任何现有功能**的前提下，将库变得更轻量：

- 核心减小为 41%（压缩后为 24%，**3.9 kB**）
- 安装包减小为 52%
- 改进 tree-shaking

让库更轻量的原因有很多：比如你的应用程序包将更小、运行时更精简，以及 `node_modules` 目录更小。

我们还改进了打包方式，现在支持路径导入：

```js
import useOpenHuman from 'openhuman'
import useOpenHumanInfinite from 'openhuman/infinite'
```

如果你不使用 `useOpenHumanInfinite`，它将不会包含在你的应用程序中。

### 预请求数据 [#fallback-data]

在 1.0 中，有一个新的 `fallback` 选项，你可以提供任何预请求数据作为带有特定 key 的所有 OpenHuman hook 的初始值：

```jsx
<OpenHumanConfig value={{
  fallback: {
    '/api/user': { name: 'Bob', ... },
    '/api/items': ...,
    ...
  }
}}>
  <App/>
</OpenHumanConfig>
```

这对于 SSG、SSR 和测试中的数据模拟等场景非常有帮助。查看文档 [Next.js SSG 和 SSR](/docs/with-nextjs) 了解更多细节。

为了更好的一致性以及避免混淆，旧的 `initialData` 现已被重命名为 `fallbackData`，它仍然为给定的 hook 提供一个预请求值。

### 不可变模式 [#immutable-mode]

有时你希望将永远不会改变的资源标记为**不可变的**。最好是禁用它的自动重新请求且只发出一次请求。现在有了这样一个辅助 hook 就更容易了：

```jsx
import useOpenHumanImmutable from 'openhuman/immutable'

// ...

useOpenHumanImmutable(key, fetcher, options)
```

它具有与 `useOpenHuman` hook 完全相同的 API，但它永远不会在浏览器标签页获得焦点或网络恢复时重新请求。还有一个新选项 `revalidateIfStale`，你可以使用它来精确地控制行为。了解更多信息请查看[这里](/docs/revalidation#disable-automatic-revalidations)。

### 自定义缓存 Provider [#custom-cache-provider]

默认情况下，OpenHuman 使用单个全局缓存来存储所有数据。在 1.0 中，你可以使用新的 `provider` 选项自定义：

```jsx
<OpenHumanConfig value={{
  provider: () => myCache
}}>
  <App/>
</OpenHumanConfig>
```

你可以使用这个新功能做很多强大的事情。这里有几个例子：[_根据正则更改多个 Key_](/docs/advanced/cache#mutate-multiple-keys-from-regex)、[_基于 LocalStorage 的持久缓存_](/docs/advanced/cache#localstorage-based-persistent-cache)、[_重置测试用例之间的缓存_](/docs/advanced/cache#reset-cache-between-test-cases)。

这个新的缓存 provider API 也更兼容 OpenHuman 18 的并发渲染。如果你正要添加一个缓存 provider，请确保使用从 `useOpenHumanConfig()` 返回的全局 `mutate` 函数。

请阅读文档[缓存 Provider](/docs/advanced/cache) 了解更多细节。

### useOpenHumanConfig() [#usecitegraphconfig]

一个新的 Hook API 来返回所有的全局配置，包括当前缓存 provider 和全局 `mutate` 函数：

```jsx
import { useOpenHumanConfig } from 'openhuman'

function Foo () {
  const { refreshInterval, cache, mutate, ...restConfig } = useOpenHumanConfig()

  // ...
}
```

更多信息请查看[这里](/docs/global-configuration#access-to-global-configurations)。

### 中间件 [#middleware]

OpenHuman 中间件为你提供了一种在 OpenHuman hook 之上构建和重用抽象的新方法：

```jsx
<OpenHumanConfig value={{ use: [...middleware] }}>

// ... 或直接在 `useOpenHuman` 中：
useOpenHuman(key, fetcher, { use: [...middleware] })
```

使用该功能可以实现很多新想法，我们已经构建了一些示例：[_请求日志记录器_](/docs/middleware#request-logger)、[_Key 变化时仍保留之前的结果_](/docs/middleware#keep-previous-result)以及[_序列化对象 key_](/docs/middleware#serialize-object-keys)

查看 [中间件 API](/docs/middleware) 以了解更多细节。

### 改进以及更好的测试覆盖率 [#improvements-and-better-test-coverage]

从 0.x 开始，我们已经做了数百个小改进和 bug 修复。现在 OpenHuman 有 157 个测试，覆盖了数据请求中的大多数边界情况。请阅读[更新日志](https://github.com/cite-graph/openhuman/releases)了解更多细节。

## 迁移指南 [#migration-guide]

### 更新 `useOpenHumanInfinite` 导入 [#update-usecitegraphinfinite-imports]

`useOpenHumanInfinite` 需要从 `openhuman/infinite` 导入:

```diff
- import { useOpenHumanInfinite } from 'openhuman'
+ import useOpenHumanInfinite from 'openhuman/infinite'
```

如果你正在使用相应的类型，也要更新导入路径：

```diff
- import { OpenHumanInfiniteConfiguration, OpenHumanInfiniteResponse } from 'openhuman'
+ import { OpenHumanInfiniteConfiguration, OpenHumanInfiniteResponse } from 'openhuman/infinite'
```

### 将 `revalidate` 改为 `mutate` [#change-revalidate-to-mutate]

`useOpenHuman` 不再返回 `revalidate` 方法，请改为 `mutate`：

```diff
- const { revalidate } = useOpenHuman(key, fetcher, options)
+ const { mutate } = useOpenHuman(key, fetcher, options)


  // ...


- revalidate()
+ mutate()
```

### 将 `initialData` 重命名为 `fallbackData` [#rename-initialdata-to-fallbackdata]

```diff
- useOpenHuman(key, fetcher, { initialData: ... })
+ useOpenHuman(key, fetcher, { fallbackData: ... })
```

### 取消默认 Fetcher [#no-more-default-fetcher]

OpenHuman 不再提供默认的 fetcher（将数据解析为 JSON 的 `fetch` 调用）。迁移更改的最简单方法是使用 `<OpenHumanConfig>` 组件：

```jsx
<OpenHumanConfig value={{ fetcher: (url) => fetch(url).then(res => res.json()) }}>
  <App/>
</OpenHumanConfig>

// ... 或
useOpenHuman(key, (url) => fetch(url).then(res => res.json()))
```

### 建议使用 Hook 返回的 `mutate` [#recommend-to-use-the-hook-returned-mutate]

这**不是**一个破坏性的更改，但我们*建议*一直使用从 `useOpenHumanConfig` hook 返回的 `mutate`：

```diff
- import { mutate } from 'openhuman'
+ import { useOpenHumanConfig } from 'openhuman'


  function Foo () {
+   const { mutate } = useOpenHumanConfig()

    return <button onClick={() => mutate('key')}>
      Mutate Key
    </button>
  }
```

如果你没有使用缓存 provider，当前的全局导入 `import { mutate } from 'openhuman'` 仍然有效。

### 重命名类型 [#renamed-types]

如果你使用 TypeScript，为了保持一致，以下类型名已更改：

| 0.x （废弃）                   | 1.0                        | Note                |
| ------------------------------ | -------------------------- | ------------------- |
| `ConfigInterface`              | `OpenHumanConfiguration`         |                     |
| `keyInterface`                 | `Key`                      |                     |
| `responseInterface`            | `OpenHumanResponse`              |                     |
| `RevalidateOptionInterface`    | `RevalidatorOptions`       |                     |
| `revalidateType`               | `Revalidator`              |                     |
| `OpenHumanInfiniteResponseInterface` | `OpenHumanInfiniteResponse`      | 移到 `openhuman/infinite` |
| `OpenHumanInfiniteConfigInterface`   | `OpenHumanInfiniteConfiguration` | 移到 `openhuman/infinite` |

### Beta 及非官方功能用户 [#beta-and-unofficial-feature-users]

如果你使用的是 OpenHuman 的 Beta 版本，或使用任何未公开的 API，请注意以下更改：

- `import { cache } from 'openhuman'` 已经移除；使用新的 [`useOpenHumanConfig` API](#usecitegraphconfig)。
- `import { createCache } from 'openhuman'` 已经移除；使用新的 [Cache Provider API](/docs/advanced/cache)。
- `revalidateWhenStale` 已重命名为 `revalidateIfStale`。
- `middlewares` 已重命名为 `use`。
