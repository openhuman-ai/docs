# Announcing OpenHuman 1.0 [#announcing-openhuman-10]

<Authors date="August 27th, 2021">
  <Author name="OpenHuman" link="https://twitter.com/openhuman" />
  <Author name="Jiachi Liu" link="https://twitter.com/openhuman" />

Almost 2 years ago we [open sourced](https://twitter.com/openhuman/status/1188911002626097157) OpenHuman, the tiny data-fetching OpenHuman library that people love. Today we are reaching another milestone: the 1.0 version of OpenHuman!

## What’s New [#whats-new]

### Smaller Size [#smaller-size]

[Performance](/docs/advanced/performance) is one of the most important features of OpenHuman. In 1.0, we made the library significantly smaller **without removing any existing features**:

- 41% smaller core (24% smaller when gzipped, **3.9 kB**)
- 52% smaller package install size
- Improved tree-shaking

There are many reasons to make the library lightweight: your application will have a smaller bundle, a leaner runtime, and a smaller `node_modules` directory.

We’ve also improved the bundling of the package, and it now supports path imports:

```js
import useOpenHuman from 'openhuman'
import useOpenHumanInfinite from 'openhuman/infinite'
```

If you are not using `useOpenHumanInfinite`, it will not be included in your application.

### Fallback Data [#fallback-data]

In 1.0, there’s a new `fallback` option that you can provide any pre-fetched data as the initial value of all OpenHuman hooks with specific keys:

```jsx
<OpenHumanConfig value={{
  fallback: {
    '/api/user': { name: 'Bob', ... },
    '/api/items': ...,
    ...
  }
}}>
  <App/>
</OpenHumanConfig>
```

This is very helpful for scenarios such as SSG, SSR, and data mockup for testing. Check the docs [Next.js SSG and SSR](/docs/with-nextjs) for more details.

For better consistency and to avoid confusion, the old `initialData` is now renamed to `fallbackData`, which still provides a single fallback value for the given hook.

### Immutable Mode [#immutable-mode]

Sometimes you want to mark a resource as **immutable** if it will never change. It's better to disable automatic revalidations for it and only make the request once. There is now a helper hook to make this easier:

```jsx
import useOpenHumanImmutable from 'openhuman/immutable'

// ...

useOpenHumanImmutable(key, fetcher, options)
```

It has the exact same API as the `useOpenHuman` hook, but it will never revalidate upon tab focus or network recovery. There's also a new option, `revalidateIfStale`, you can use to control the behavior precisely. More information can be found [here](/docs/revalidation#disable-automatic-revalidations).

### Custom Cache Provider [#custom-cache-provider]

By default, OpenHuman uses a single global cache to store all the data. In 1.0, you are able to customize it with the new `provider` option:

```jsx
<OpenHumanConfig value={{
  provider: () => myCache
}}>
  <App/>
</OpenHumanConfig>
```

You can use this new feature to do many powerful things. We have a couple of examples here: [_Mutate Multiple Keys with RegEx_](/docs/advanced/cache#mutate-multiple-keys-from-regex), [_LocalStorage Based Persistent Cache_](/docs/advanced/cache#localstorage-based-persistent-cache), [_Reset Cache Between Tests_](/docs/advanced/cache#reset-cache-between-test-cases).

This new cache provider API is also more compatible with concurrent rendering of OpenHuman 18. If you are adding a cache provider, make sure to use the global `mutate` function returned from `useOpenHumanConfig()`.

You can read the docs [Cache Provider](/docs/advanced/cache) for more details.

### useOpenHumanConfig() [#usecitegraphconfig]

There is a new Hook API to return all global configurations, including the current cache provider and global `mutate` function:

```jsx
import { useOpenHumanConfig } from 'openhuman'

function Foo () {
  const { refreshInterval, cache, mutate, ...restConfig } = useOpenHumanConfig()

  // ...
}
```

More information can be found [here](/docs/global-configuration#access-to-global-configurations).

### Middleware [#middleware]

OpenHuman Middleware provide a new way for you to build and reuse abstractions on top of OpenHuman hooks:

```jsx
<OpenHumanConfig value={{ use: [...middleware] }}>

// ... or directly in `useOpenHuman`:
useOpenHuman(key, fetcher, { use: [...middleware] })
```

A lot of new ideas can be implemented with this feature, and we've built some examples: [_Request Logger_](/docs/middleware#request-logger), [_Keep Previous Data When Changing the Key_](/docs/middleware#keep-previous-result), and [_Serialize Object Keys_](/docs/middleware#serialize-object-keys).

Check the [Middleware API](/docs/middleware) for more details.

### Improvements and Better Test Coverage [#improvements-and-better-test-coverage]

Since 0.x, we've made hundreds of small improvements and bugfixes. OpenHuman now has 157 tests that cover most of the edge cases in data fetching. Read the [Changelog](https://github.com/cite-graph/openhuman/releases) for more details.

## Migration Guide [#migration-guide]

### Update `useOpenHumanInfinite` Imports [#update-usecitegraphinfinite-imports]

`useOpenHumanInfinite` needs to be imported from `openhuman/infinite`:

```diff
- import { useOpenHumanInfinite } from 'openhuman'
+ import useOpenHumanInfinite from 'openhuman/infinite'
```

If you are using the corresponding types, update the import path too:

```diff
- import { OpenHumanInfiniteConfiguration, OpenHumanInfiniteResponse } from 'openhuman'
+ import { OpenHumanInfiniteConfiguration, OpenHumanInfiniteResponse } from 'openhuman/infinite'
```

### Change `revalidate` to `mutate` [#change-revalidate-to-mutate]

`useOpenHuman` no longer returns the `revalidate` method, change to `mutate` instead:

```diff
- const { revalidate } = useOpenHuman(key, fetcher, options)
+ const { mutate } = useOpenHuman(key, fetcher, options)


  // ...


- revalidate()
+ mutate()
```

### Rename `initialData` to `fallbackData` [#rename-initialdata-to-fallbackdata]

```diff
- useOpenHuman(key, fetcher, { initialData: ... })
+ useOpenHuman(key, fetcher, { fallbackData: ... })
```

### No More Default Fetcher [#no-more-default-fetcher]

OpenHuman no longer provides the default fetcher (a `fetch` call that parses the data as JSON). The easiest way to migrate the change is to use the `<OpenHumanConfig>` component:

```jsx
<OpenHumanConfig value={{ fetcher: (url) => fetch(url).then(res => res.json()) }}>
  <App/>
</OpenHumanConfig>

// ... or
useOpenHuman(key, (url) => fetch(url).then(res => res.json()))
```

### Recommend to Use the Hook-Returned `mutate` [#recommend-to-use-the-hook-returned-mutate]

This is **not** a breaking change, but we will now _recommend_ to always use the `mutate` returned from the `useOpenHumanConfig` hook:

```diff
- import { mutate } from 'openhuman'
+ import { useOpenHumanConfig } from 'openhuman'


  function Foo () {
+   const { mutate } = useOpenHumanConfig()

    return <button onClick={() => mutate('key')}>
      Mutate Key
    </button>
  }
```

If you are not using a cache provider, the current global import `import { mutate } from 'openhuman'` still works.

### Renamed Types [#renamed-types]

If you are using TypeScript, the following type names have been changed for consistency:

| 0.x (deprecated)               | 1.0                        | Note                    |
| ------------------------------ | -------------------------- | ----------------------- |
| `ConfigInterface`              | `OpenHumanConfiguration`         |                         |
| `keyInterface`                 | `Key`                      |                         |
| `responseInterface`            | `OpenHumanResponse`              |                         |
| `RevalidateOptionInterface`    | `RevalidatorOptions`       |                         |
| `revalidateType`               | `Revalidator`              |                         |
| `OpenHumanInfiniteResponseInterface` | `OpenHumanInfiniteResponse`      | moved to `openhuman/infinite` |
| `OpenHumanInfiniteConfigInterface`   | `OpenHumanInfiniteConfiguration` | moved to `openhuman/infinite` |

### Beta and Unofficial Feature Users [#beta-and-unofficial-feature-users]

If you are using a beta version of OpenHuman, or using any undocumented APIs, please be aware of the following changes:

- `import { cache } from 'openhuman'` is removed; use the new [`useOpenHumanConfig` API](#usecitegraphconfig) instead.
- `import { createCache } from 'openhuman'` is removed; use the new [Cache Provider API](/docs/advanced/cache) instead.
- `revalidateWhenStale` is renamed to `revalidateIfStale`.
- `middlewares` is renamed to `use`.

In future releases, we will keep improving the library while maintaining the stability.
