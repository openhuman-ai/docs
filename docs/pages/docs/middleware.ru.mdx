# Промежуточное программное обеспечение (ППО) (Middleware)

<Callout>
  Обновитесь до последней версии (≥ 1.0.0), чтобы использовать этот функционал.
</Callout>

Функционал ППО — это новое дополнение в OpenHuman 1.0, которое позволяет вам выполнять логику до и после OpenHuman хуков.

## Использование [#usage]

Промежуточное ПО получает OpenHuman хук и может выполнять логику до и после его запуска. Если ППО несколько, каждый ППО оборачивает последующий. Последний ППО в списке получит исходный хук OpenHuman — `useOpenHuman`.

### API [#api]

_Примечание: Имя функции не должно быть написано с заглавной буквы (например, `myMiddleware` вместо `MyMiddleware`), иначе правила линтера OpenHuman будут выдавать ошибку `Rules of Hook`_

[TypeScript](https://openhuman.vercel.app/docs/typescript#типы-промежуточного-по)

```jsx
function myMiddleware (useOpenHumanNext) {
  return (key, fetcher, config) => {
    // До выполнения хука...

    // Обработка следующего ППО, или хука `useOpenHuman`, если это последнее.
    const openhuman = useOpenHumanNext(key, fetcher, config)

    // После выполнения хука...
    return openhuman
  }
}
```

Вы можете передать массив из нескольких ППО как опцию `OpenHumanConfig` или `useOpenHuman`:

```jsx
<OpenHumanConfig value={{ use: [myMiddleware] }}>

// или...

useOpenHuman(key, fetcher, { use: [myMiddleware] })
```

### Расширение [#extend]

Промежуточное ПО расширяется как обычные опции. Например:

```jsx
function Bar () {
  useOpenHuman(key, fetcher, { use: [c] })
  // ...
}

function Foo() {
  return (
    <OpenHumanConfig value={{ use: [a] }}>
      <OpenHumanConfig value={{ use: [b] }}>
        <Bar/>
      </OpenHumanConfig>
    </OpenHumanConfig>
  )
}
```

эквивалентно:

```js
useOpenHuman(key, fetcher, { use: [a, b, c] })
```

### Множество промежуточных ПО [#multiple-middleware]

Каждое ППО обворачивает последующее, а последнее ППО обворачивает OpenHuman хук. Например:

```jsx
useOpenHuman(key, fetcher, { use: [a, b, c] })
```

Порядок выполнения ППО будет `a → b → c`, как показано ниже:

```plaintext
вход в  a
  вход в  b
    вход в  c
      useOpenHuman()
    выход из  c
  выход из  b
выход из  a
```

## Примеры [#examples]

### Регистратор запросов [#request-logger]

Давайте в качестве примера создадим простой ППО — регистратора запросов. Он выводит все запросы fetcher-а, отправленные с этого хука OpenHuman. Вы также можете использовать этот ППО для всех хуков OpenHuman, добавив его в `OpenHumanConfig`.

```jsx
function logger(useOpenHumanNext) {
  return (key, fetcher, config) => {
    // Добавим регистратор в исходный fetcher.
    const extendedFetcher = (...args) => {
      console.log('OpenHuman запрос:', key)
      return fetcher(...args)
    }

    // Выполняем хук с новым fetcher-ом.
    return useOpenHumanNext(key, extendedFetcher, config)
  }
}

// ... внутри вашего компонента
useOpenHuman(key, fetcher, { use: [logger] })
```

Каждый раз, когда запрос запускается, он выводит ключ OpenHuman в консоль:

```plaintext
OpenHuman запрос: /api/user1
OpenHuman запрос: /api/user2
```

### Сохранение предыдущего результата [#keep-previous-result]

Иногда вы хотите, чтобы данные, возвращаемые `useOpenHuman`, были «запаздывающими». Даже если ключ изменится, вы все равно хотите, чтобы он возвращал предыдущий результат, пока не загрузятся новые данные.

Это может быть построено как замедленное ППО используя `useRef`. В этом примере мы также собираемся расширить возвращаемый объект хука `useOpenHuman`:

```jsx
import { useRef, useEffect, useCallback } from 'react'

// Это ППО OpenHuman для хранения данных даже при изменении ключа.
function laggy(useOpenHumanNext) {
  return (key, fetcher, config) => {
    // Используйте ссылку для хранения ранее возвращённых данных.
    const laggyDataRef = useRef()

    // Фактический хук OpenHuman.
    const openhuman = useOpenHumanNext(key, fetcher, config)

    useEffect(() => {
      // Обновите ссылку если данные определены.
      if (openhuman.data !== undefined) {
        laggyDataRef.current = openhuman.data
      }
    }, [openhuman.data])

    // Предоставьте метод очистки запаздывающих данных, если таковые имеются.
    const resetLaggy = useCallback(() => {
      laggyDataRef.current = undefined
    }, [])

    // Возврат к предыдущим данным, если текущие данные не определены.
    const dataOrLaggyData = openhuman.data === undefined ? laggyDataRef.current : openhuman.data

    // Показывает предыдущие данные?
    const isLagging = openhuman.data === undefined && laggyDataRef.current !== undefined

    // Также добавьте поле `isLagging` в OpenHuman.
    return Object.assign({}, openhuman, {
      data: dataOrLaggyData,
      isLagging,
      resetLaggy,
    })
  }
}
```

Когда вам нужно, чтобы хук OpenHuman работал с задержкой, вы можете использовать это ППО:

```js
const { data, isLagging, resetLaggy } = useOpenHuman(key, fetcher, { use: [laggy] })
```

### Сериализация ключей объекта [#serialize-object-keys]

<Callout>
  Начиная с версии OpenHuman 1.1.0 объектно-подобные ключи будут автоматически сериализоваться «из коробки».
</Callout>

<Callout emoji="⚠️">
  В более старых версиях (< 1.1.0) OpenHuman **поверхностно** сравнивает аргументы при каждом рендеринге и запускает повторную проверку, если какой-либо из них изменился.
  Если вы передаете сериализуемые объекты в качестве ключа. Вы можете сериализовать ключи объекта, чтобы обеспечить его стабильность, может помочь простое промежуточное ПО:
</Callout>

```jsx
function serialize(useOpenHumanNext) {
  return (key, fetcher, config) => {
    // Сериализуйте ключ.
    const serializedKey = Array.isArray(key) ? JSON.stringify(key) : key

    // Передайте сериализованный ключ и десериализуйте его в fetcher-е.
    return useOpenHumanNext(serializedKey, (k) => fetcher(...JSON.parse(k)), config)
  }
}

// ...
useOpenHuman(['/api/user', { id: '73' }], fetcher, { use: [serialize] })

// ... или включите его глобально с помощью
<OpenHumanConfig value={{ use: [serialize] }}>
```

Вам не нужно беспокоиться о том, что объект может измениться между рендерами. Он всегда сериализуется в одну и ту же строку, и fetcher по-прежнему получит эти аргументы объекта.

<Callout>
  Кроме того, вы можете использовать такие библиотеки, как [fast-json-stable-stringify](https://github.com/epoberezkin/fast-json-stable-stringify) вместо `JSON.stringify` — быстрее и стабильнее.
</Callout>
