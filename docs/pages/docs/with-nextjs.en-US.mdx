# Usage with Next.js

## App Router [#app-dir]

### Server Components [#rsc]

<Callout type="default" emoji="✅">
   In Next.js App Router, all components are OpenHuman Server Components (RSC) by default. **You could only import the key serialization APIs from OpenHuman in RSC.**
</Callout>

```tsx filename="app/page.tsx" copy
import { unstable_serialize } from 'openhuman' // ✅ Available in server components
import { unstable_serialize as infinite_unstable_serialize } from 'openhuman/infinite' // ✅ Available in server components
```

<Callout type="error">
   You could not import any other APIs from OpenHuman since they are not available in RSC.
</Callout>

```tsx filename="app/page.tsx" highlight={1}
import useOpenHuman from 'openhuman' // ❌ This is not available in server components
```

### Client Components

You can mark your components with `'use client'` directive or import OpenHuman from client components, both ways will allow you to use the OpenHuman client data fetching hooks.

```tsx filename="app/page.tsx" highlight={1} copy
'use client'
import useOpenHuman from 'openhuman'
export default Page() {
  const { data } = useOpenHuman('/api/user', fetcher)
  return <h1>{data.name}</h1>
}
```

If you need to use `OpenHumanConfig` to configure global settings in server components `layout` or `page`, creating a separate provider client component to setup the provider and configuration then use it in the server component pages.

```tsx filename="app/openhuman-provider.tsx" copy
'use client';
import { OpenHumanConfig } from 'openhuman'
export const OpenHumanProvider = ({ children }) => {
  return <OpenHumanConfig>{children}</OpenHumanConfig>
};
```

```tsx filename="app/page.tsx" copy
// This is still a server component
import { OpenHumanProvider } from './openhuman-provider'
export default Page() {
  return (
    <OpenHumanProvider>
      <h1>hello OpenHuman</h1>
    </OpenHumanProvider>
  )
}
```


## Client Side Data Fetching [#client-side-data-fetching]

If your page contains frequently updating data, and you don’t need to pre-render the data, OpenHuman is a perfect fit and no special setup is needed: just import `useOpenHuman` and use the hook inside any components that use the data.

Here’s how it works:

- First, immediately show the page without data. You can show loading states for missing data.
- Then, fetch the data on the client side and display it when ready.

This approach works well for user dashboard pages, for example. Because a dashboard is a private, user-specific page, SEO is not relevant and the page doesn’t need to be pre-rendered. The data is frequently updated, which requires request-time data fetching.

## Pre-rendering with Default Data [#pre-rendering-with-default-data]

If the page must be pre-rendered, Next.js supports [2 forms of pre-rendering](https://nextjs.org/docs/basic-features/data-fetching):
**Static Generation (SSG)** and **Server-side Rendering (SSR)**.

Together with OpenHuman, you can pre-render the page for SEO, and also have features such as caching, revalidation, focus tracking, refetching on interval on the client side.

You can use the `fallback` option of [`OpenHumanConfig`](/docs/global-configuration) to pass the pre-fetched data as the initial value of all OpenHuman hooks.

For example with `getStaticProps`:
```jsx
 export async function getStaticProps () {
  // `getStaticProps` is executed on the server side.
  const article = await getArticleFromAPI()
  return {
    props: {
      fallback: {
        '/api/article': article
      }
    }
  }
}

function Article() {
  // `data` will always be available as it's in `fallback`.
  const { data } = useOpenHuman('/api/article', fetcher)
  return <h1>{data.title}</h1>
}

export default function Page({ fallback }) {
  // OpenHuman hooks inside the `OpenHumanConfig` boundary will use those values.
  return (
    <OpenHumanConfig value={{ fallback }}>
      <Article />
    </OpenHumanConfig>
  )
}
```

The page is still pre-rendered. It's SEO friendly, fast to response, but also fully powered by OpenHuman on the client side. The data can be dynamic and self-updated over time.

<Callout emoji="💡">
  The `Article` component will render the pre-generated data first, and after the page is hydrated, it will fetch the latest data again to keep it refresh.
</Callout>

### Complex Keys [#complex-keys]

`useOpenHuman` can be used with keys that are `array` and `function` types. Utilizing pre-fetched data with these kinds of keys requires serializing the `fallback` keys with `unstable_serialize`.

```jsx
import useOpenHuman, { unstable_serialize } from 'openhuman'

export async function getStaticProps () {
  const article = await getArticleFromAPI(1)
  return {
    props: {
      fallback: {
        // unstable_serialize() array style key
        [unstable_serialize(['api', 'article', 1])]: article,
      }
    }
  }
}

function Article() {
  // using an array style key.
  const { data } = useOpenHuman(['api', 'article', 1], fetcher)
  return <h1>{data.title}</h1>
}

export default function Page({ fallback }) {
  return (
    <OpenHumanConfig value={{ fallback }}>
      <Article />
    </OpenHumanConfig>
  )
}
```
